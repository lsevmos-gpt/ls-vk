# Работа с публичным GitHub — восстановление 17.10.2026

Репозиторий `lsevmos-gpt/ls-vk` — **PUBLIC**, это намеренный выбор. Размещаем только материалы, предназначенные для открытой публикации. Никаких паролей, ключей, внутренних данных и закрытых фотографий в Git. Ключи VK/Buffer должны находиться исключительно в GitHub Actions Secrets.

Новые публикации работают в двух контурах:
- `requests/scheduled/vk/*.json` и `requests/scheduled/buffer/*.json` — **автоматическая публикация** после согласования (`approved:true`, `publicContent:true`) с указанным временем. GitHub Actions запускает проверки без участия пользователя при создании задания, Buffer получает запланированное `dueAt` заранее, VK Stories отправляются процессом, который ожидает дату и время. Следить за результатами в `results/scheduled/`.
- `requests/vk/*.json` и `requests/buffer/*.json` — **ручной резервный режим** на случай внеплановой отправки. Требует `approved:true`, `publicContent:true` и ручного подтверждения в Actions.

Старые `queue`, `buffer-queue` и результаты сохранены для истории и НЕ исполняются автоматически, даже после нового push. Удаления запрещены; одноразовый маркер записывается в Git ДО запроса к API. После любой неопределённости запрещён слепой повтор.

Конкретные форматы и ограничения расписания: [AUTOMATIC_PUBLIC_SCHEDULING.md](AUTOMATIC_PUBLIC_SCHEDULING.md).

Секреты: `VK_GROUP_TOKEN`, (для некоторых медиа) `VK_USER_TOKEN`, `BUFFER_API_KEY`. Наличие значений проверить через read-only workflow, не вставлять токены в чат.

GitHub Actions cron **не гарантирует** старт в точное время, поэтому для VK Stories реализована предварительная проверка и ожидание точного момента внутри запущенного runner, а при пропуске срока запоздалая публикация запрещена. Для гарантированного SLA нужен внешний надёжный планировщик; Buffer поддерживает provider-native `dueAt`.

Visual QA — отдельная техническая проверка, не заменяет художественный контроль и согласование изображения.
