# «Линия спорта» — техническая политика максимального качества для соцсетей

**Статус:** действующее правило для всех последующих публикаций Instagram, ВК, Stories, Reels, Клипов, фото и обложек.

## Основной принцип

Публиковать оригинал максимально возможного качества с учётом реальных ограничений платформы. Нельзя снижать разрешение, частоту кадров, видеобитрейт или качество фотографий ради ускорения загрузки либо экономии места, если платформа принимает оригинал. Исходный файл не заменять ухудшенной версией.

1. **Не перекодировать без необходимости.** При совместимых параметрах передавать исходные байты на медиахостинг; если платформа допускает исходный кодек и размер, использовать этот же файл. Для контроля фиксировать SHA-256 исходника, размеры, формат и источник.
2. **Видео:** сохранять исходное разрешение, ориентацию, fps и видеопоток. При требованиях платформы к аудио или контейнеру по возможности исправлять только несовместимый компонент (например, перекодировать только AAC-аудио или перепаковать MP4 с `-c:v copy`), не переписывая исходный видеопоток. Создавать отдельную производную копию и документировать отличие.
3. **Фото:** не допускать многократного пересохранения JPEG. Логотипы, графику, баннеры и обложки, содержащие текст, хранить в PNG без потерь; исходные фотографии — в максимально качественной совместимой форме с корректным цветовым профилем (sRGB при необходимости).
4. **Форматы:** выбирать нужные пропорции для Reels/Stories (обычно 9:16) и отображения в ленте согласно актуальным правилам площадки. Не обрезать заголовки и логотип. Не повышать разрешение искусственно в целях мнимого улучшения детализации.
5. **Обложки:** всегда сохранять исходные PNG отдельными файлами. Для **автоматической публикации Reels через Buffer** отдельную PNG-обложку API не принимает; проверенная нами схема (ролик Рустама, 15.10.2026): перед публикацией встроить утверждённую вертикальную обложку в начало MP4 на **0,40 секунды**, а в Buffer указать `metadata.thumbnailOffset: 0` миллисекунд и `shouldShareToFeed: true`. Для отдельного превью сетки 4:5 хранить оригинальную версию, но не обещать автоматическое применение — в подтверждённой интеграции Buffer такой функции нет. Проверять фактическую обложку после публикации. Вставка заставки требует создания отдельной видео-копии и повторного кодирования видео при несовместимости потоков: использовать максимально качественные настройки, неизменное исходное разрешение и fps (если допустимо), сохранить оригинал без модификаций. **Нельзя размещать новый Reels повторно только ради исправления обложки без прямого поручения пользователя**.
6. **Проверка перед отправкой:** технический анализ ffprobe (кодеки, профили, длительность, fps, битрейты, размер); визуальный просмотр вступления, ключевых этапов и завершения; проверка полного вертикального кадра; публичной доступности медиафайла для провайдера до даты публикации; уникальность задания и запрет случайного дубля.
7. **Подтверждение факта:** «отправлено/запланировано» не равно «опубликовано». При планировании сохранять provider ID и указанное время, после события проверять результат в Instagram/ВК. При сомнительном результате не повторять отправку без проверки, чтобы избежать дублей.
8. **Безопасность:** не коммитить пароли и токены в публичный GitHub; использовать только Actions Secrets; публичные ссылки только для заранее одобренных к публикации материалов.
