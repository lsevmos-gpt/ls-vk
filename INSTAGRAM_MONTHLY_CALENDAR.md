# Календарь Instagram «Линии спорта» — только Meta API

## Что это

Независимая от ChatGPT система для планирования на месяц и дольше. Пользователь
самостоятельно добавляет в календарь Reels (с соавторами или без), фото,
карусели и Stories. GitHub Actions проверяет расписание, публикует через
настроенный Meta Graph API и сохраняет результаты.

**Buffer API НЕ используется** этим календарём.

**Важно:** система использует GitHub Actions по cron раз в 5 минут и не
гарантирует попадание в точную минуту. Github может задержать либо пропустить
cron-событие. Видеоконтейнер Meta также обрабатывается несколько минут.
Поэтому это автономный планировщик **best effort**, а не решение с SLA по
точности времени. Для точного времени потребуется отдельный непрерывно
работающий сервер/облачный исполнитель, создающий контейнеры до публикации.

## Самостоятельно добавить публикацию без ChatGPT

1. Открыть GitHub Actions → [Add Instagram calendar post (Meta only)](https://github.com/lsevmos-gpt/ls-vk/actions/workflows/instagram-calendar-add.yml).
2. Нажать **Run workflow**, выбрать **main**.
3. Заполнить поля:
   - **post_type** — reel, photo, carousel или story;
   - **publish_time** — по Симферополю / Москве: 2026-11-14 12:30;
   - **media_urls** — общедоступные HTTPS адреса .mp4/.mov/.jpg/.jpeg.
     Для карусели несколько адресов через точку с запятой; тип определяется
     по расширению. Можно явно написать image:https://...jpg;
     video:https://...mp4;
   - **caption** — окончательно утверждённый текст (для story пустое поле);
   - **cover_url** — JPG/JPEG обложка для Reel;
   - **collaborators** — для Reel до трёх @username, через запятую;
   - **share_to_feed** — показывать Reel также в основной сетке;
   - **approved** — отметить только после окончательного утверждения;
   - **public_content** — подтвердить, что материалы и тексты можно
     размещать в ПУБЛИЧНОМ репозитории GitHub.
4. Нажать запуск. Workflow **только записывает** новое задание в календарь,
   публиковать немедленно оно ничего не будет.
5. Следить за расписанием: [calendar/instagram](https://github.com/lsevmos-gpt/ls-vk/tree/main/calendar/instagram).
   Файлы разбиты по месяцам: YYYY-MM/ig-....json.
6. Фактические результаты появляются в
   [results/scheduled/instagram](https://github.com/lsevmos-gpt/ls-vk/tree/main/results/scheduled/instagram).
   В них: id, исходная дата, статус и media ID, если Meta подтвердило публикацию.

Планирование разрешено за 20 минут — 365 дней до публикации. Можно
подготовить **весь месяц заранее**, заполнив форму для каждого материала.
Точная минута может сдвигаться: см. ограничение выше.

### Просмотр ожидающих публикаций

[Instagram Meta monthly calendar](https://github.com/lsevmos-gpt/ls-vk/actions/workflows/instagram-meta-calendar.yml)
→ Run workflow → operation=preview. Этот режим **не публикует** ничего.
Автоматический cron публикует утверждённые задания в назначенные даты.

### Изменить или отменить запланированное

До начала публикации открыть нужный JSON-файл в calendar/instagram/YYYY-MM/
через GitHub → Edit. Можно изменить publishAt, text, media, coverUrl или
collaborators; сохранить commit. Для отмены поставить approved=false.
Если дата переносится в другой месяц, переместить файл в каталог нового месяца.
Изменения не влияют на уже опубликованные или уже зарезервированные записи.

**ВАЖНО:** Нельзя просто убрать / перезапустить запись, если в results
появился статус submission_started или manual_review_required.
Meta могла уже создать публикацию. Сначала обязательно вручную сверить
Instagram, чтобы не разместить дубликат. Результат published означает
подтверждение API, но не принятие приглашения соавтором.

## Как работает автономный процесс

- GitHub cron (раз в 5 минут) проверяет календарь без участия ChatGPT.
- Обрабатывает только approved=true + publicContent=true, аккаунт строго
  @liniya__sporta; никакие черновики не публикует.
- Работает с текущим META_IG_ACCESS_TOKEN и META_IG_USER_ID из GitHub Secrets.
- Если запуск произошёл чуть заранее — ожидает запланированное время.
- Если GitHub пришёл позже более чем на 15 минут — помечает missed_window
  **без публикации**, чтобы не размещать несвоевременный контент.
- Перед Meta POST надёжно резервирует job ID и пишет это в git.
  Повторный запуск по этому же ID блокируется.
- Публикует медиа через Meta API, сохраняет media ID и статус.
- Обрабатывает за запуск одно ближайшее задание; не следует назначать много
  публикаций на одну минуту. Следующая проверка подберёт последующие записи.

Срок действия Page Access Token не гарантирован. Для планирования на месяц
нужен долгосрочный токен/управление обновлением, а не короткий токен из Graph
API Explorer. При истечении токена публикация не выйдет. Нужно следить за
проверкой Meta и GitHub Actions уведомлениями о сбоях.

## Важное ограничение конфиденциальности

Репозиторий lsevmos-gpt/ls-vk сейчас **PUBLIC**.
Нельзя помещать сюда конфиденциальные сведения, чужие персональные данные,
ещё не предназначенные для публичного распространения тексты или медиа.
Если требуется хранить закрытые кампании на месяц до выхода, нужно
**отдельное защищённое хранилище** для планов, а исходные медиа заранее
безопасно размещать на HTTPS-хостинге, доступном Meta в момент публикации.
Не делайте репозиторий приватным без проверки: текущие публичные ссылки на
исходные видео из raw.githubusercontent.com могут перестать работать.

## Ограничения Meta

- Истории с наклейкой кликабельной ссылки, репост чужих Stories и некоторые
  музыкальные, стикерные и прочие UI-функции не доступны через API.
- Stories через API с Facebook Login требуют Instagram Business аккаунта
  (для Creator ограничена поддержка).
- Фото: JPEG. Видео: MP4 или MOV с поддерживаемыми кодеками.
- Карусели: 2–10 изображений/видео; соавторство в этой реализации
  поддерживается только для Reels.
- Публикации могут быть ограничены квотой и состоянием Instagram-аккаунта.
- Для планирования на месяц **медиа должны быть доступны Meta в момент
  публикации**, ссылки не должны истекать раньше срока.
- Запланированное видео не загружается в Meta заранее; его обработка после
  назначения времени может добавить задержку.

## Код и тесты

- scripts/instagram_meta_calendar.py — нормализация, выбор даты, Meta
  Content Publishing API, защищённая обработка и журнал.
- scripts/instagram_calendar_add.py — пользовательская форма, сохранение
  утверждённой записи.
- .github/workflows/instagram-meta-calendar.yml — cron, preview, проверки.
- .github/workflows/instagram-calendar-add.yml — форма добавления записи.
- tests/test_instagram_meta_calendar.py, tests/test_instagram_calendar_add.py
  — тесты без вызовов Meta.

Ни один unit test и validation job не публикует материалы. Для реальных фото,
Stories и каруселей после доработки всё равно желательно провести
контрольные публикации с согласованными публичными материалами до полной
деактивации Buffer.
