# Публичные материалы и автоматическая публикация по времени (lsevmos-gpt/ls-vk)

Репозиторий может быть PUBLIC: никаких токенов, паролей, внутренних данных, необнародованных фотографий клиентов или коммерческой информации сюда не помещать. `approved=true` подтверждает согласование, `publicContent=true` — явное разрешение разместить контент в общедоступном репозитории.

### Instagram Stories

Добавить новый файл `requests/scheduled/buffer/<id>.json` с уникальным ID, типом `instagram`, `postType: story`, `publishNow: false`, `approved: true`, `publicContent: true`, `handle: liniya__sporta`, `publishAt: 2026-10-17T10:00:00+03:00`, `dueAt: 2026-10-17T07:00:00Z`, `media: [{"type":"image","url":"https://.../public-image.png"}]`, `text: ""`, `isAiGenerated: true/false` по фактическому материалу. Коммит инициирует проверку, после чего **Buffer получает scheduled post заранее** через `mode:customScheduled`, а опубликование в назначенное время выполняет сам Buffer (фактический вывод зависит от Buffer и Instagram). Результат в `results/scheduled/buffer/<id>.json` содержит ID поста и точный `dueAt`. Не использовать Metricool. Ссылка должна вести на реально доступный без авторизации файл.

### VK Stories

Добавить новый файл `requests/scheduled/vk/<id>.json`: `type:story`, `approved:true`, `publicContent:true`, `publishAt` с часовым поясом, `storyType:photo`, `media:media/<имя>.png` (публичный файл в репозитории) либо `mediaUrl` публичного файла, `addToNews:true`.

GitHub Actions запускает дежурную проверку в 04,19,34,49 минут каждого часа (cron GitHub — UTC), **во время работы runner ожидает точное назначенное время перед обращением к VK API**. Если Action запустился слишком поздно, публикация пропускается, а не выходит не вовремя. Важное ограничение: GitHub Actions может задержать или пропустить запуск cron, поэтому фактическое попадание в заданную минуту НЕ гарантируется. Для строгой SLA нужна отдельная постоянно работающая служба/cron на хостинге; GitHub Actions сам по себе не является гарантированным real-time планировщиком.

### Защита от дублей

Перед первым обращением к провайдеру неизменно резервируется `results/scheduled/<platform>/<id>.json` и сохраняется в GitHub. Любая неопределённость = ручная сверка перед новой попыткой. Старые `queue/`, `buffer-queue/` не запускаются; прежние результаты сохраняются. Новые публикации разрешены только с `approved:true`, `publicContent:true`, точным временем и новым ID. Готовые Stories, фото и логотипы проверяются перед коммитом согласно визуальным правилам. Ни один планировщик не подтверждает художественное качество.
