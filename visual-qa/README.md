# Visual QA — «Линия спорта»

Это **отдельный, не публикующий** технический контроль для макетов Stories и других изображений. Исходные фото, списки дней рождения и логотипы остаются в **Google Drive**; для независимого тестирования точные копии конкретных исходных файлов допускается помещать в GitHub **ТОЛЬКО ПОСЛЕ перевода lsevmos-gpt/ls-vk в Private**. Пока репозиторий публичный — не размещать фотографии сотрудников, логотипы и черновики здесь.

## Источник правил

Google Drive → `Линия спорта / 00_ФИРМЕННЫЙ_СТИЛЬ_MASTER / 03_ПРАВИЛА_И_ГАЙДЫ`:

- `00_AI_EXECUTION_RULES_v1.2.txt` и `Liniya_Sporta_SMM_Quality_Gates_v1.2.json`;
- актуальный v1.2 визуальный гайд;
- шесть утверждённых оригинальных логотипов от **16.10.2026** (SHA-256 в `00_MASTER_ASSETS_SHA256.csv`). Старые файлы логотипов запрещены.

Для поздравительных Stories также действуют более конкретные правила и реестр из `Линия спорта / Дни рождения сотрудников`.

## Проверка нового макета

После подтверждения, что репозиторий **Private**, создать каталог `visual-qa/submissions/<job-id>/` с файлами:

- `manifest.json` — схема ниже;
- `final.png` — действительно экспортированный макет, не растянутый старый файл;
- `photo.jpg` — точный оригинал с Google Drive;
- `logo.png` — точный новый MASTER PNG;
- `composition.svg` — редактируемый макет с реальными текстовыми слоями и встраиванием исходного JPEG и логотипа как двух отдельных изображений (base64 bytes без изменения содержимого).

Пример **схемы, не готовое задание и не разрешение на публикацию**:

```json
{
  "schema_version": 1,
  "id": "birthday-anna-2026-10-17",
  "format": "story",
  "source": {
    "display_name": "АННА",
    "google_drive_photo_id": "1299EJ27_qt3FC9tQXfbH_RL_rLOzg_NT",
    "registry_drive_file_id": "16Zi0NH2QWtI8YujwmrMvLKfGE9m-Ow8A",
    "photo_sha256": "ВСТАВИТЬ_РЕАЛЬНЫЙ_SHA256_ОРИГИНАЛА",
    "logo_master_filename": "лого т_белый.png",
    "logo_master_sha256": "be3937ff7c9df8e1f93adcbbbc7a574dbe85eae2fbaccf9b5e467f3eb611e66e"
  },
  "files": {
    "final": "final.png",
    "photo": "photo.jpg",
    "logo": "logo.png",
    "svg": "composition.svg"
  }
}
```

Путь обязателен именно под `submissions/`, к имени каталога применяются ограничения безопасного идентификатора. **Не коммитить секреты, токены, ключи OAuth и .env.** В приватном GitHub у копий фотографий остаётся дополнительный доступ GitHub; доступ сотрудников необходимо учитывать отдельно. Публичные URL исходников не нужны.

Пуш в `main` запускает Action **Visual QA — technical preflight (never publish)**. Ручная проверка доступна через Actions → этот workflow → Run workflow. Локально: `pip install Pillow`, затем `python -m unittest discover -s visual_qa_tests -v` и `python -m scripts.visual_quality_gate scan`.

## Что означает результат

- `BLOCKED` — техническое несоответствие, макет забракован; выпуск запрещён.
- `TECHNICAL_PASS_REVIEW_REQUIRED` — проверены реальные байты, хеши, размеры, структура SVG, формат PNG, базовые шрифты/поля и цвет. **Это НЕ «готово», НЕ P01–P10 PASS, НЕ художественное одобрение и НЕ разрешение публиковать.**
- `NO_VISUAL_SUBMISSIONS` — нет ни одного проверенного реального макета.

**Техническая проверка не доказывает** личность на фотографии, неизменность внешности после визуального рендера, композиционную выразительность, праздничное настроение, реальные габариты каждой буквы, точность данных в онлайн-реестре. Все эти проверки должны выполняться по исходникам человеком и фиксироваться **отдельно**, с предъявлением макета на утверждение. Сам ChatGPT не должен выставлять оценку художественного качества как независимый эксперт.

**ВАЖНО:** этот workflow **не связан с** `social-publish-manual.yml`, не модифицирует `queue/`, `requests/`, секреты и не включает/производит публикации. Жёсткая техническая блокировка самого действия публикации будет возможна после подключения этой проверки как preflight к ручному publishing workflow и согласования порядка передачи приватных исходников. Пока публикационный workflow и QA существуют раздельно; не выдавать это за enforced gate.
